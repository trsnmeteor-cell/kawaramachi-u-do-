# 河原町 誘導ログ — セットアップ手順

河原町エリアのカラオケ6店舗間で発生する「顧客誘導」を、その場で記録し、Googleチャットへ自動投稿するアプリです。
記録は Google スプレッドシートに貯まり、集計タブで期間・自店舗・誘導先の3条件で絞り込めます。

---

## 1. ファイル構成

```
index.html                 アプリ本体（これ1枚で動作します）
manifest.webmanifest       PWA 設定
sw.js                      Service Worker（オフライン起動・自動更新）
version.json               現在のバージョン情報（更新検知に使用）
icons/                     アプリアイコン
gas/Code.gs                サーバー側のコード（Google Apps Script に貼る）
tools/bump-version.py      バージョン一括更新スクリプト
README.md                  このファイル
```

アプリは静的ファイルなので、HTTPS で配信できればどこでも動きます（社内サーバー／Netlify／GitHub Pages など）。
PWA としてインストールできるのは HTTPS 配信時のみです（`file://` で開くとインストールはできませんが、動作はします）。

| 用意するもの | 入手場所 |
|---|---|
| Google アカウント | ― |

## 3. サーバー側（Google Apps Script）の設定 ★ここだけ手作業

1. https://script.google.com を開き、「新しいプロジェクト」を作成
2. `gas/Code.gs` の中身をすべてコピーして、エディタの内容を置き換えて保存
3. 右上「デプロイ」→「新しいデプロイ」
   - 種類：**ウェブアプリ**
   - 説明：任意（例 `yudo-log v1`）
   - 実行ユーザー：**自分**
   - アクセスできるユーザー：**全員**
4. 「デプロイ」→ 表示された **ウェブアプリのURL（`…/exec`）** をコピー
5. 初回は権限の確認が出ます →「許可」→ 自分のアカウントを選択 →「詳細」→「（プロジェクト名）に移動」→ 許可

> コードを直したときは「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」で再デプロイしてください。
> URL は変わりません。
> **v1.1.1 で Code.gs に CORS 対応を追加しました。それ以前のコードを使っている場合は必ず再デプロイしてください。**

### 動作確認

ブラウザで `（ウェブアプリのURL）?action=ping` を開き、
`{"ok":true,"data":{"pong":true,…}}` が表示されれば成功です。

## 3.5 更新の配り方（自動更新）

アプリは **ファイルを差し替えるだけで、各端末が自動で新版に切り替わります**。利用者に「再読み込みしてください」と案内する必要はありません。

### 手順

1. 次のコマンドでバージョンを3か所そろえて更新します

   ```
   python3 tools/bump-version.py 1.2.0 "変更内容のメモ"
   ```

   （手作業でも可：`index.html` の `APP_VERSION`、`sw.js` の `VERSION`、`version.json` の `version` を同じ番号に）

2. `index.html` などを上書きアップロード（Netlify ならフォルダを再ドロップ）

### 各端末での動き

| タイミング | 動作 |
|---|---|
| アプリを開いている間 | 5分ごとに `version.json` を確認。新しければ**キャッシュを破棄して自動再読み込み** |
| アプリに戻ってきたとき | 同じく確認 → 自動更新 |
| 更新を検知したとき | 操作中なら画面下に「新しいバージョンがあります／更新する」を表示。**15秒以上操作がなければ自動で更新**、タブを離れた場合も更新 |
| 登録処理中 | 絶対に再読み込みしません（送信完了後に更新） |
| オフライン | 更新は保留。次にオンラインで開いたときに適用 |

> **番号を上げ忘れると更新されません。** `sw.js` の `VERSION` が更新検知のトリガーです。必ず `bump-version.py` を使ってください。

## 3.9 公開（アップロード）手順

初回公開の順番は **① GAS → ② 設定値の控え → ③ 静的ファイルのアップロード → ④ アプリで設定 → ⑤ 端末登録** です。

### ① GAS を先にデプロイ
`gas/Code.gs` を貼り付けて「デプロイ → 新しいデプロイ → ウェブアプリ / 実行＝自分 / アクセス＝全員」。
表示された `…/exec` URL を控える。
（このコードは CORS ヘッダーを返すので、別ドメインのページから読み書きできます）

### ② スプレッドシートと Webhook を用意
- スプレッドシートを新規作成 → URL を控える（見出し行はアプリが自動作成）
- Google チャットのスペース → 「アプリと統合」→「Webhook を追加」→ URL を控える

### ③ 静的ファイルをアップロード（HTTPS）
zip を展開し、`index.html` がある階層をそのまま公開します。

- **Netlify Drop**（最短）: https://app.netlify.com/drop にフォルダをドラッグ → 発行 URL を取得
  - 匿名のドロップは**パスワード保護され、他人からは開けません**。「Claim」してアカウントに紐づけると公開されます
- **GitHub Pages**: リポジトリに push → Settings → Pages → ブランチ指定
- **Cloudflare Pages / 社内サーバー**: いずれもフォルダを置くだけ

### ④ アプリで接続設定
公開 URL を開く → 「接続設定」を開いて 3 つの URL を貼る → 保存 → **接続テスト**。
「接続できました」が出れば完了。「設定リンクをコピー」で他端末へ配布できます。

### ⑤ 端末にインストール
- **iPhone/iPad**: Safari で開く → 共有 → 「ホーム画面に追加」
- **Android**: Chrome で開く → メニュー → 「アプリをインストール」
- **PC**: Chrome/Edge のアドレスバー右のインストールアイコン、または画面右上の「インストール」

## 4. アプリの配置

`index.html` `manifest.webmanifest` `sw.js` `icons/` を**同じフォルダ構成のまま** HTTPS で配信します。

- **Netlify Drop**（いちばん簡単）：https://app.netlify.com/drop にこのフォルダをドラッグ＆ドロップ → 発行されたURLをそのまま利用
- **GitHub Pages**：リポジトリにフォルダを push → Settings → Pages → ブランチを指定
- **社内サーバー**：Apache / Nginx などに置くだけ（HTTPS 推奨）

---

## 5. アプリ側の設定

アプリを開き、画面最上部の **「接続設定」バーをタップして開き**（アコーディオン式）、3つを貼り付けて **保存する**。
右端のバッジが「設定済み」になれば完了です。閉じても内容は保持されます。

| 項目 | 内容 |
|---|---|
| Googleチャット Webhook URL | 手順2で取得した URL |
| スプレッドシート URL | 記録先シートの URL（`https://docs.google.com/spreadsheets/d/…`） |
| Apps Script Webアプリ URL | 手順3-4でコピーした `…/exec` の URL |

「接続テスト」を押して「接続できました」が出れば準備完了です。

### 他の端末（タブレット・PC）へ配布

「設定リンクをコピー」を押すと、3つの設定が埋め込まれたURLができます。
そのURLを他端末のブラウザで開くだけで、同じ設定が入ります（各端末で1回だけ）。

## 6. 使い方

### 登録タブ
1. 自店舗・誘導先店舗を選ぶ（⇄ ボタンで入れ替え）
2. 人数を 1〜30 で入力（−／＋ またはプリセット）
3. 「登録する」

ボタンを押すと画面全体がロックされ、**「登録中。しばらくお待ちください。」** が表示されます。処理が終わるまでボタン・選択・タブはすべて操作できません（連打による二重登録を防止）。

押した瞬間に以下が実行されます。

- **Googleチャットへ投稿**：`三条河原町店→京都河原町近江屋店　3名　1415`
- **スプレッドシートへ1行追記**：日付／時刻／自店舗／誘導先／人数／記録ID

上部のLCD表示には、送信される文面がリアルタイムでプレビューされます。

### 集計タブ
- **期間**：今日／直近7日／今月／全期間／日付指定
- **自店舗**・**誘導先店舗**：すべて／各店舗

絞り込んだ結果に対して、誘導人数・件数・1件あたりの平均・最多ルート、日別グラフ、店舗別マトリクス、明細（CSV出力可）を表示します。
データは **8秒ごとに自動更新** されるので、他店が登録した内容もそのまま反映されます。

## 7. 仕組みと注意点

- **同時利用**：書き込みは Apps Script のロックで直列化されるため、複数端末から同時に押しても行が壊れません。
- **二重登録の防止**：1件ごとに記録IDを発行し、再送時はシート側で重複を判定してスキップします。
- **オフライン時**：電波が無い場合は端末内に「未送信」として保持し、復帰後に自動送信します（今日の登録に「未送信」バッジが出ます）。
- **時刻**：端末の時計ではなく日本時間（Asia/Tokyo）で記録します。端末の時計が24時間以上ずれている場合はサーバー時刻を使います。
- **セキュリティ**：WebアプリURLとWebhook URLを知っている人は誰でも記録・投稿できます。URLは社内のみで共有してください。「設定リンク」にも同じURLが含まれます。

## 8. うまく動かないとき

| 症状 | 確認すること |
|---|---|
| 「サーバーに接続できません」 | デプロイの「アクセスできるユーザー」が **全員** になっているか／URLが `…/exec` で終わっているか |
| シートに書かれない | スプレッドシートURLが正しいか／GASを実行したアカウントがそのシートの編集権限を持っているか |
| チャットに投稿されない | Webhook URL が正しいか（スペース側で削除されていないか）／「シートには記録しました」と出た場合はWebhookだけの問題です |
| 画面が古いまま | `sw.js` の `VERSION` を上げて再アップロードしたか確認。それでも古い場合はスーパーリロード（Ctrl+Shift+R） |
| インストールボタンが出ない | HTTPS で開いているか（`file://` では出ません） |
